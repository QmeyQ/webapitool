# OPERATIONS
1. SkipPreference

Definition: Select this action when the new preference is semantically similar to an existing preference and provides no significant new information, details, or modifications.

Selection Criteria:
- The new preference conveys the exact same intent as the old one, perhaps with slightly different wording.
- The information is redundant.

Examples:

New preference: "prefer camel naming style"
Old preference: "prefer camel variable" (similar)
Action: SkipPreference

New preference: "I like apples"
Old preference: "The user likes apples"
Action: SkipPreference

2. AddPreference

Definition: Select this action when the new preference contains relevant, lasting information that is not currently present in the existing preferences.

Selection Criteria:
- The information represents a new preference, constraint, or fact about the user.
- There is no existing preference that covers this topic.

Examples:

New preference: "I'm allergic to peanuts"
Old preference: "" (No allergy information exists)
Action: AddPreference

New preference: "I prefer dark mode for all interfaces"
Old preference: "The user likes coding in Python"
Action: AddPreference

3. UpdatePreference

Definition: Select this action when the new preference relates to an existing preference but provides additional details, modifications, new context, or conflicts with the existing preference.

Selection Criteria:
- Refinement: The core concept already exists in records, and this new preference enhances or refines it. (e.g., severity, sub-genre).
- Conflict Resolution: The new preference contradicts or conflicts with an existing preference. In this case, the new preference takes precedence, and the old one should be updated/replaced.

Examples:

- Scenario A (Refinement):
  - New preference: "I especially love space operas"
  - Old preference: "The user enjoys science fiction"
  - Action: UpdatePreference

- Scenario B (Conflict/Replacement):
  - New preference: "coding with java"
  - Old preference: "coding with python"
  - Action: UpdatePreference (The old Python preference is updated/replaced by the new Java preference)

- Scenario C (Specifics):
  - New preference: "My peanut allergy is severe and requires an EpiPen"
  - Old preference: "The user is allergic to peanuts"
  - Action: UpdatePreference
